## Why

Every Crow HR module holds personal data (NRIC/FIN, salary, bank, medical) about other people. Before any module ships, we need sign-in, sessions, roles and a tamper-evident audit trail that every route uses. These must be enforced server-side in `packages/core` so the same rules hold in Node, in tests and in the in-browser demo. The foundation ships a fail-closed `requireAuth` that always returns 401; this change makes it real.

## What Changes

- **Email + password sign-in.** Argon2id via the injected hasher, a password policy, per-account and per-IP throttling, email reset with a copy-link fallback when SMTP is absent, optional TOTP MFA with recovery codes, and an MFA requirement for privileged roles (default on).
- **Database-backed sessions.** HttpOnly `__Host-` cookie, idle and absolute timeouts, session list with revoke, re-authentication for sensitive actions, and CSRF protection.
- **One OIDC implementation** (`openid-client`) with presets for Google Workspace (hosted-domain restriction), Microsoft Entra ID (tenant restriction, required), Singpass (FAPI 2.0: PAR, PKCE, `private_key_jwt`, DPoP) and generic OIDC. Secrets and keys are encrypted at rest.
- **Linking.** SSO identities link only to pre-provisioned users. Just-in-time (JIT) provisioning is optional, limited to allowed domains and off by default. The owner's password login always works as break-glass.
- **Invitations** create pre-provisioned memberships.
- **Roles.** Five fixed roles: `owner`, `hr_admin`, `payroll_admin`, `manager` (derived from reporting lines, covering direct and indirect reports) and `employee` (implicit). A resource × action × role permission matrix is enforced on every route.
- **Field-level sensitivity.** Four classes (`salary`, `nric`, `bank`, `medical`). Fields are omitted for unauthorised readers, NRIC/FIN is masked (`S****567D`) with an audited reveal, and NRIC/FIN and bank numbers are encrypted at rest.
- **Org-level data isolation.** Org-scoped data access, composite foreign keys, and a shared cross-org test helper.
- **Append-only audit log** with a per-org hash chain, read rules and export.
- **Demo mode.** SSO buttons stay visible but are disabled with an explanation, and a browser-safe hasher is substituted.

## Capabilities

### New Capabilities
- `auth`: password and SSO sign-in, MFA, sessions, invitations, sign-in method configuration, demo behaviour.
- `access-control`: roles, permission matrix, manager and self scopes, field sensitivity and NRIC masking, encryption of sensitive identifiers, org isolation, audit log.

### Modified Capabilities
None. The foundation's `requireAuth` contract (401 when unauthenticated) is kept.

## Non-goals

- Custom roles or per-org permission editing (P1). The matrix is fixed in code.
- Passkeys/WebAuthn, SMS OTP, email OTP.
- SCIM or directory sync. Entra/Google group-to-role mapping.
- MyInfo data pre-fill via Singpass.
- Postgres row-level security. App-level scoping plus composite FKs is the v1 control, and RLS is a later defence-in-depth option.
- Key-rotation tooling. Ciphertexts carry a key ID so rotation can be added later.
- Integration API tokens (P1). Mobile device tokens and `/api/v1` versioning are in `add-api-platform`.
- Self-signup of new organisations on a shared install beyond the first-run owner setup.

## Impact

- `packages/core`: new `auth/`, `access/`, `audit/` and `crypto/` modules; schema files `auth.ts`, `access.ts`, `audit.ts`; a real `requireAuth` and an `authorize()` middleware; `GET /api/v1/me`.
- New injected deps: `Mailer` (optional), `SecretBox` (AES-256-GCM from `CROWHR_SECRET_KEY`), and an `Rng` already covered by Web Crypto.
- `apps/server`: env `CROWHR_SECRET_KEY` (auto-generated by `add-self-hosting` when absent), `PUBLIC_URL`, `SMTP_*`; a CLI `crowhr admin reset-owner-password`.
- `apps/web`: sign-in, invite acceptance, reset, MFA enrolment, Settings → Security, Members, Audit log, My sessions.
- New dependencies: `openid-client` (v6, runtime-agnostic), a TOTP implementation on Web Crypto (no Node deps), and a bundled common-password list.
- Every later module depends on `authorize()`, the scope resolver and `audit.record()`.
